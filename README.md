# REQ-ML

Research-oriented MATLAB toolbox for adaptive radial energy-quantile (REQ) estimation and local shear-wave-speed mapping in harmonic shear-wave elastography.

REQ-ML consumes reproducible `wavefield_sample.mat` outputs generated by the companion `shear-wave-simulation-framework` repository. This repository is responsible for patch extraction, REQ feature and target construction, dataset coverage analysis, model training, and evaluation.

> **Research status:** active research software. Interfaces and model definitions may change before the first stable release. This code is not intended for clinical use or medical decision-making.

## Method overview

REQ estimates a representative local wavenumber from the cumulative radial energy of a windowed wavefield patch.

```text
E_cum(k) = integral_0^k S_rad(k') dk'
           / integral_0^kmax S_rad(k') dk'
```

A quantile `q` selects `k_q`:

```text
E_cum(k_q) = q
```

and the corresponding shear-wave speed is

```text
c_s = 2*pi*f0/k_q
```

The adaptive workflow studies whether local spectral, cumulative-energy, acquisition, and composition features can predict an operational value of `q` without using true SWS during inference.

## Current scientific objective

The current objective is to build a new final REQ-ML training dataset from clean projected-3D Eikonal simulations.

The simulation campaign will be adaptive and reproducible. It will stop when patch-level coverage criteria are met, rather than after a fixed number of simulations.

The main coverage dimensions are:

- patch material purity;
- measured field diffusivity;
- local true SWS;
- excitation frequency.

Geometry is not the learning target. Homogeneous, bilayer, and circular-inclusion media are controlled mechanisms for generating pure and mixed-material patches.

## Reproducibility requirements

Every active dataset and model must be traceable to:

- repository commit;
- resolved configuration;
- source simulation campaign and run IDs;
- simulation and planner seeds;
- dataset identity;
- split manifest;
- training configuration;
- evaluation outputs.

Models or datasets without this information are exploratory artifacts.

## Output policy

Generated artifacts belong under `outputs/` and are excluded from version control. Versioned source code, configurations, manifests, and concise interpretation documents belong in Git.

## Evaluation principles

Performance claims must use held-out or explicitly external data. Patches from the same run or physical condition must not be split across training and evaluation partitions.

Evaluation should report:

- absolute and percentage error;
- bias;
- tail and high-error rates;
- invalid-prediction rate;
- variability across runs and seeds;
- performance by purity, diffusivity, SWS, frequency, and geometry family.

## Companion simulation repository

Physical simulation generation is maintained in:

```text
https://github.com/gsara798/shear-wave-simulation-framework
```

That repository owns media, propagation, wavefield generation, and simulation provenance. REQ-ML owns local analysis, dataset construction, adaptive coverage, training, and evaluation.

## Limitations

- This is a research codebase, not a validated clinical product.
- Eikonal simulations are controlled approximations rather than full elastodynamic solutions.
- Patches from one wavefield are correlated and must not be treated as independent experimental runs.
- Patch purity cannot be guaranteed before patch extraction; it is measured after simulation.
- Angular entropy is useful but is not a complete description of wavefield geometry.
